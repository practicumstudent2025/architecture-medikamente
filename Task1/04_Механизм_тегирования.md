# Механизм тегирования данных

## 1. Концепция тегирования

Тегирование данных позволяет автоматически применять политики безопасности на основе метаданных. Каждый набор данных или файл получает теги, которые определяют уровень конфиденциальности и требуемые меры защиты.

## 2. Структура тегов

### 2.1. Основные категории тегов

#### Категория: `confidentiality`
Определяет уровень конфиденциальности данных:
- `confidentiality:public` - Публичные данные
- `confidentiality:internal` - Внутренние данные
- `confidentiality:confidential` - Конфиденциальные данные
- `confidentiality:restricted` - Ограниченного доступа
- `confidentiality:top-secret` - Строго конфиденциальные

#### Категория: `sensitivity`
Определяет чувствительность данных:
- `sensitivity:low` - Низкая чувствительность
- `sensitivity:medium` - Средняя чувствительность
- `sensitivity:high` - Высокая чувствительность
- `sensitivity:critical` - Критическая чувствительность

#### Категория: `data-type`
Тип данных:
- `data-type:medical` - Медицинские данные
- `data-type:pii` - Персональные данные
- `data-type:financial` - Финансовые данные
- `data-type:operational` - Операционные данные
- `data-type:analytics` - Аналитические данные

#### Категория: `retention`
Политика хранения:
- `retention:1year` - Хранение 1 год
- `retention:3years` - Хранение 3 года
- `retention:5years` - Хранение 5 лет
- `retidential:10years` - Хранение 10 лет
- `retention:indefinite` - Бессрочное хранение

#### Категория: `external`
Внешние взаимодействия:
- `external:laboratory` - Данные для лаборатории
- `external:partner` - Данные для партнёров
- `external:none` - Только внутреннее использование

#### Категория: `compliance`
Требования соответствия:
- `compliance:152-fz` - Требования 152-ФЗ
- `compliance:medical` - Медицинские требования
- `compliance:financial` - Финансовые требования

## 3. Примеры тегирования данных

### 3.1. Медицинская карта пациента
```
confidentiality:restricted
sensitivity:critical
data-type:medical
retention:10years
external:none
compliance:152-fz,medical
```

## 4. Инструменты тегирования

- Автоматическое обнаружение и тегирование данных
- Интеграция с AWS S3, RDS, DynamoDB

### 4.2. Microsoft Purview Information Protection
- Автоматическая классификация данных
- Тегирование на основе контента
- Интеграция с Office 365, Azure

### 4.3. Apache Atlas (для Data Lake)
- Управление метаданными
- Тегирование данных в Data Lake
- Отслеживание происхождения данных (Data Lineage)

### 4.4. HashiCorp Vault
- Управление секретами с тегами
- Автоматическое применение политик на основе тегов

### 4.5. Кастомное решение на базе:
- **Metadata Management System** - централизованное хранилище метаданных
- **Tagging API** - API для программного тегирования
- **Policy Engine** - движок применения политик на основе тегов

## 5. Автоматическое применение политик

### 5.1. Правила применения политик

#### Правило 1: Шифрование
```
IF confidentiality:restricted OR sensitivity:critical
THEN encrypt:true, algorithm:AES-256
```

#### Правило 2: Контроль доступа
```
IF data-type:medical AND sensitivity:critical
THEN access:rbac, roles:[doctor, admin], audit:true
```

#### Правило 3: Резервное копирование
```
IF retention:10years OR retention:indefinite
THEN backup:enabled, frequency:daily, retention:30days
```

#### Правило 4: Мониторинг
```
IF sensitivity:high OR sensitivity:critical
THEN monitoring:enabled, alerting:true
```

#### Правило 5: Внешняя передача
```
IF external:laboratory
THEN encryption:required, api:mtls, audit:required
```

## 6. Процесс тегирования данных

### 6.1. Автоматическое тегирование
1. **При создании данных** - система автоматически определяет тип данных
2. **При загрузке файлов** - сканирование содержимого и автоматическое тегирование
3. **При интеграции** - теги наследуются от источника данных

### 6.2. Ручное тегирование
1. **Администратор данных** - может добавлять/изменять теги
2. **Владелец данных** - может устанавливать теги для своих данных
3. **Аудит изменений** - все изменения тегов логируются

### 6.3. Валидация тегов
1. **Проверка обязательных тегов** - система требует наличие определённых тегов
2. **Проверка конфликтов** - обнаружение противоречивых тегов
3. **Автоматическая коррекция** - предложение правильных тегов

## 7. Интеграция с системами

### 7.1. База данных
- Теги хранятся как метаданные таблиц/колонок
- Применение политик на уровне запросов

### 7.2. Файловое хранилище
- Теги в расширенных атрибутах файлов
- Интеграция с файловой системой

### 7.3. API Gateway
- Теги в заголовках запросов
- Валидация тегов при передаче данных

### 7.4. Data Lake
- Теги в метаданных объектов
- Автоматическое применение политик при обработке
