# Механизм тегирования данных

## 1. Структура тегов

### Основные категории:

**`confidentiality`**: public, internal, confidential, restricted, top-secret

**`sensitivity`**: low, medium, high, critical

**`data-type`**: medical, pii, financial, operational, analytics

**`retention`**: 1year, 3years, 5years, 10years, indefinite

**`external`**: laboratory, partner, none

**`compliance`**: 152-fz, medical, financial

## 2. Примеры тегирования

### Медицинская карта:
```
confidentiality:restricted
sensitivity:critical
data-type:medical
retention:10years
external:none
compliance:152-fz,medical
```

### Результаты анализов:
```
confidentiality:restricted
sensitivity:high
data-type:medical
retention:5years
external:laboratory
compliance:152-fz,medical
```

### Персональные данные:
```
confidentiality:confidential
sensitivity:high
data-type:pii
retention:5years
external:none
compliance:152-fz
```

## 3. Инструменты тегирования

- **AWS Data Classification** - автоматическое обнаружение и тегирование
- **Microsoft Purview Information Protection** - классификация данных
- **Apache Atlas** - управление метаданными для Data Lake
- **HashiCorp Vault** - управление секретами с тегами
- **Кастомное решение** - Metadata Management System + Tagging API + Policy Engine

## 4. Автоматическое применение политик

**Правило 1 - Шифрование**:
```
IF confidentiality:restricted OR sensitivity:critical
THEN encrypt:true, algorithm:AES-256
```

**Правило 2 - Контроль доступа**:
```
IF data-type:medical AND sensitivity:critical
THEN access:rbac, roles:[doctor, admin], audit:true
```

**Правило 3 - Резервное копирование**:
```
IF retention:10years OR retention:indefinite
THEN backup:enabled, frequency:daily
```

**Правило 4 - Мониторинг**:
```
IF sensitivity:high OR sensitivity:critical
THEN monitoring:enabled, alerting:true
```

**Правило 5 - Внешняя передача**:
```
IF external:laboratory
THEN encryption:required, api:mtls, audit:required
```

## 5. Процесс тегирования

- **Автоматическое**: При создании данных, при загрузке файлов, при интеграции
- **Ручное**: Администратор/владелец данных может добавлять/изменять теги
- **Валидация**: Проверка обязательных тегов, обнаружение конфликтов

## 6. Интеграция с системами

- **База данных**: Теги как метаданные таблиц/колонок
- **Файловое хранилище**: Теги в расширенных атрибутах
- **API Gateway**: Теги в заголовках запросов
- **Data Lake**: Теги в метаданных объектов

## 7. Мониторинг

- Дашборд тегов: Визуализация распределения данных
- Аудит тегов: История изменений
- Соответствие: Проверка обязательных тегов, отчёты о соответствии
