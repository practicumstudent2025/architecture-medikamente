# Список проблемных зон системы безопасности «Медикаменте»

## 1. Проблемы хранения данных

### 1.1. Отсутствие шифрования
- **Проблема**: Все данные хранятся в открытом виде (Excel, JPG, PDF)
- **Риск**: При компрометации файлового сервера все данные доступны злоумышленнику
- **Критичность**: Высокая

### 1.2. Централизованное хранение без разграничения
- **Проблема**: Все данные на общем диске, доступны всем сотрудникам
- **Риск**: Несанкционированный доступ к данным других пациентов
- **Критичность**: Критическая

### 1.3. Отсутствие резервного копирования
- **Проблема**: Нет систематического резервного копирования
- **Риск**: Потеря данных при сбоях оборудования
- **Критичность**: Высокая

## 2. Проблемы контроля доступа

### 2.1. Недостаточная аутентификация
- **Проблема**: Только доменная аутентификация, нет MFA
- **Риск**: Компрометация учётной записи = полный доступ к данным
- **Критичность**: Высокая

### 2.2. Отсутствие RBAC/ABAC
- **Проблема**: Нет ролевой модели доступа, все сотрудники имеют равные права
- **Риск**: Сотрудник ресепшена может получить доступ к медицинским картам
- **Критичность**: Критическая

### 2.3. Нет принципа минимальных привилегий
- **Проблема**: Сотрудники имеют доступ ко всем данным, а не только к необходимым
- **Риск**: Утечка данных при компрометации любого сотрудника
- **Критичность**: Высокая

## 3. Проблемы обработки данных

### 3.1. Ручная обработка данных
- **Проблема**: Все операции выполняются вручную в Excel
- **Риск**: Ошибки при вводе, случайное удаление данных, утечки при копировании
- **Критичность**: Средняя

### 3.2. Двойной учёт
- **Проблема**: Кассиры ведут двойной учёт в Excel и 1С
- **Риск**: Расхождения в данных, сложность аудита
- **Критичность**: Средняя

### 3.3. Отсутствие валидации данных
- **Проблема**: Нет проверки корректности вводимых данных
- **Риск**: Некорректные данные в системе
- **Критичность**: Средняя

## 4. Проблемы передачи данных

### 4.1. Небезопасные каналы передачи
- **Проблема**: Данные передаются по локальной сети без шифрования
- **Риск**: Перехват данных при передаче
- **Критичность**: Высокая

### 4.2. Интеграция с лабораторией
- **Проблема**: Нет контролируемого API для передачи данных в лабораторию
- **Риск**: Несанкционированная передача данных, утечка в третьи руки
- **Критичность**: Критическая

### 4.3. Отсутствие контроля передачи
- **Проблема**: Нет логирования передачи данных третьим лицам
- **Риск**: Невозможность отследить утечку данных
- **Критичность**: Высокая

## 5. Проблемы аудита и мониторинга

### 5.1. Отсутствие аудита доступа
- **Проблема**: Нет логирования, кто и когда получал доступ к данным
- **Риск**: Невозможность выявить утечку или несанкционированный доступ
- **Критичность**: Критическая

### 5.2. Отсутствие мониторинга
- **Проблема**: Нет системы мониторинга нетипичных действий
- **Риск**: Позднее обнаружение инцидентов безопасности
- **Критичность**: Высокая

### 5.3. Нет алертинга
- **Проблема**: Отсутствие автоматических уведомлений о подозрительной активности
- **Риск**: Инциденты остаются незамеченными
- **Критичность**: Высокая

## 6. Проблемы соответствия требованиям

### 6.1. Несоответствие законодательству РФ
- **Проблема**: Работа с конфиденциальными данными не соответствует требованиям 152-ФЗ
- **Риск**: Штрафы, репутационные потери, потеря доверия клиентов
- **Критичность**: Критическая

### 6.2. Отсутствие Privacy By Design
- **Проблема**: Защита данных не заложена в архитектуру системы
- **Риск**: Сложность внедрения защиты в существующую систему
- **Критичность**: Высокая

### 6.3. Нарушение принципа Data Minimization
- **Проблема**: Собираются и хранятся избыточные данные
- **Риск**: Увеличение риска утечки, нарушение прав пациентов
- **Критичность**: Средняя

### 6.4. Отсутствие Data Lineage
- **Проблема**: Невозможно отследить происхождение и перемещение данных
- **Риск**: Сложность аудита, невозможность доказать соответствие требованиям
- **Критичность**: Высокая

## 7. Проблемы масштабируемости

### 7.1. Файловый режим 1С
- **Проблема**: 1С работает в файловом режиме, не поддерживает масштабирование
- **Риск**: Проблемы при росте нагрузки и расширении команды
- **Критичность**: Средняя

### 7.2. Локальный сервер
- **Проблема**: Физический сервер в здании офиса
- **Риск**: Риск физического доступа, проблемы при расширении филиалов
- **Критичность**: Средняя

## 8. Проблемы управления жизненным циклом данных

### 8.1. Отсутствие политик хранения
- **Проблема**: Нет определённых сроков хранения данных
- **Риск**: Накопление избыточных данных, нарушение требований
- **Критичность**: Средняя

### 8.2. Отсутствие механизма удаления
- **Проблема**: Нет автоматического удаления данных по истечении срока хранения
- **Риск**: Нарушение прав пациентов на удаление данных
- **Критичность**: Высокая

### 8.3. Нет учёта согласий
- **Проблема**: Отсутствует централизованный учёт согласий пациентов на обработку данных
- **Риск**: Обработка данных без согласия, нарушение законодательства
- **Критичность**: Критическая

## 9. Приоритизация проблем

### Критические (требуют немедленного решения):
1. Отсутствие RBAC/ABAC
2. Централизованное хранение без разграничения
3. Отсутствие аудита доступа
4. Интеграция с лабораторией без контроля
5. Несоответствие законодательству РФ
6. Нет учёта согласий пациентов

### Высокие (решить в ближайшее время):
1. Отсутствие шифрования
2. Недостаточная аутентификация
3. Небезопасные каналы передачи
4. Отсутствие мониторинга
5. Отсутствие механизма удаления данных

### Средние (решить при планировании):
1. Ручная обработка данных
2. Двойной учёт
3. Файловый режим 1С
4. Отсутствие политик хранения
