# Задание 1: Анализ безопасности системы

## Описание

Это задание посвящено анализу текущего состояния безопасности системы компании «Медикаменте» и разработке рекомендаций по улучшению защиты конфиденциальных данных.

## Структура решения

### Документы анализа

1. **01_Конфиденциальные_данные.md** - Выявленные конфиденциальные данные и их классификация
2. **02_Проблемные_зоны.md** - Список проблемных зон системы безопасности с приоритизацией
3. **03_Данные_для_защиты.md** - Список данных для защиты с указанием методов защиты (шифрование, обезличивание, обфускация)
4. **04_Механизм_тегирования.md** - Разработанный механизм тегирования данных с примерами
5. **05_Инструменты_и_меры.md** - Список инструментов, способов и мер для обеспечения конфиденциальности данных

### Диаграммы потоков данных (DFD)

#### Базовые диаграммы (As-Is):
- **DFD_Level0_Context.drawio** - Контекстная диаграмма системы (Level 0)
- **DFD_Level1_Регистрация_пациента.drawio** - Процесс регистрации пациента (Level 1)
- **DFD_Level1_Запись_к_врачу.drawio** - Процесс записи к врачу (Level 1)
- **DFD_Level1_Интеграция_с_лабораторией.drawio** - Процесс интеграции с лабораторией (Level 1)

#### Доработанные диаграммы (To-Be с защитой):
- **DFD_Level1_Регистрация_пациента_с_защитой.drawio** - Процесс регистрации с мерами защиты
- **DFD_Level1_Интеграция_лаборатория_с_защитой.drawio** - Интеграция с лабораторией с мерами защиты

## Ключевые выводы

### Выявленные конфиденциальные данные:
- Персональные данные (ФИО, дата рождения, телефон, email, адрес)
- Медицинские данные (диагнозы, результаты анализов, медицинские карты)
- Финансовые данные (платежная информация, данные договоров)
- Операционные данные (журналы записей, история посещений)

### Критические проблемные зоны:
1. Отсутствие RBAC/ABAC - нет ролевой модели доступа
2. Централизованное хранение без разграничения
3. Отсутствие аудита доступа
4. Интеграция с лабораторией без контроля
5. Несоответствие законодательству РФ (152-ФЗ)
6. Нет учёта согласий пациентов

### Рекомендуемые меры защиты:

#### Шифрование:
- **At Rest**: AES-256 для всех конфиденциальных данных
- **In Transit**: TLS 1.3 для всех передач данных, mTLS для API

#### Контроль доступа:
- RBAC с ролями: Doctor, Reception, Cashier, Accountant, Admin
- ABAC на основе тегов данных
- MFA для всех сотрудников

#### Мониторинг и аудит:
- Логирование всех обращений к конфиденциальным данным
- SIEM для обнаружения аномалий
- DLP для предотвращения утечек

#### Тегирование:
- Автоматическое тегирование данных по уровню конфиденциальности
- Применение политик на основе тегов
- Отслеживание Data Lineage

## Принципы безопасности

При разработке решения применены следующие принципы:

1. **Privacy By Design** - защита данных заложена в архитектуру
2. **Data Minimization** - собираются только необходимые данные
3. **Data Lineage** - отслеживание происхождения и перемещения данных
4. **Defense in Depth** - многоуровневая защита
5. **Least Privilege** - принцип минимальных привилегий

## Следующие шаги

1. Внедрение шифрования (Vault, PostgreSQL encryption)
2. Настройка логирования (ELK Stack)
3. Базовый RBAC
4. Тегирование данных (Apache Atlas)
5. API Gateway с mTLS для интеграции с лабораторией
6. DLP для внешних интеграций
7. Мониторинг и алертинг
