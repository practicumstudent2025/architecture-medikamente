# Список данных для защиты и методы защиты

## 1. Медицинские карты и диагнозы

### Данные:
- Диагнозы
- Результаты анализов
- Медицинские заключения
- История лечения
- Назначения врачей

### Методы защиты:
1. **Шифрование на уровне хранения (Encryption at Rest)**
   - Алгоритм: AES-256
   - Ключи: Управление через HSM или Key Management Service
   - Применение: Все файлы медицинских карт в зашифрованном виде

2. **Шифрование при передаче (Encryption in Transit)**
   - Протокол: TLS 1.3
   - Применение: При передаче между системами, в API

3. **Обезличивание (Anonymization)**
   - Метод: Замена ФИО на псевдонимы при аналитике
   - Применение: Для BI-отчётов, ML-обучения

4. **Обфускация (Obfuscation)**
   - Метод: Маскирование чувствительных полей в логах
   - Применение: В системных логах, отладочной информации

5. **Тегирование**
   - Тег: `confidentiality:medical`, `sensitivity:high`
   - Применение: Автоматическое применение политик защиты

## 2. Персональные данные (ФИО, дата рождения, адрес)

### Данные:
- ФИО
- Дата рождения
- Адрес прописки
- Телефон
- Email

### Методы защиты:
1. **Шифрование на уровне хранения**
   - Алгоритм: AES-256
   - Применение: В базе данных, файловом хранилище

2. **Токенизация (Tokenization)**
   - Метод: Замена реальных данных на токены
   - Применение: В системах, не требующих реальных данных

3. **Маскирование (Masking)**
   - Метод: Частичное скрытие данных (например, ***@email.com)
   - Применение: В интерфейсах для сотрудников без полного доступа

4. **Хеширование (Hashing)**
   - Алгоритм: SHA-256 с солью
   - Применение: Для поиска дубликатов без раскрытия данных

5. **Тегирование**
   - Тег: `confidentiality:pii`, `sensitivity:medium`
   - Применение: Контроль доступа на основе тегов

## 3. Финансовые данные

### Данные:
- Платежная информация
- Суммы оплаты
- Данные договоров
- Бухгалтерские данные

### Методы защиты:
1. **Шифрование на уровне хранения**
   - Алгоритм: AES-256
   - Применение: В 1С, базах данных

2. **Шифрование при передаче**
   - Протокол: TLS 1.3
   - Применение: При интеграции с платёжными системами

3. **Сегментация сети**
   - Метод: Изоляция финансовых данных в отдельном сегменте
   - Применение: Ограничение доступа по сети

4. **Тегирование**
   - Тег: `confidentiality:financial`, `sensitivity:high`
   - Применение: Строгий контроль доступа

## 4. Журналы записей и операционные данные

### Данные:
- Журналы записей к специалистам
- Расписание приёмов
- История посещений

### Методы защиты:
1. **Шифрование на уровне хранения**
   - Алгоритм: AES-256
   - Применение: В базе данных

2. **Обезличивание**
   - Метод: Удаление прямых идентификаторов при аналитике
   - Применение: Для статистических отчётов

3. **Тегирование**
   - Тег: `confidentiality:operational`, `sensitivity:low`
   - Применение: Контроль доступа

## 5. Результаты анализов лаборатории

### Данные:
- Результаты анализов
- Реестры анализов
- Данные для передачи в лабораторию

### Методы защиты:
1. **Шифрование при передаче**
   - Протокол: TLS 1.3, mTLS для API
   - Применение: При передаче в лабораторию

2. **Шифрование на уровне хранения**
   - Алгоритм: AES-256
   - Применение: В хранилище

3. **API Security**
   - Метод: OAuth 2.0, JWT токены
   - Применение: Контроль доступа к API

4. **Data Loss Prevention (DLP)**
   - Метод: Сканирование передаваемых данных
   - Применение: Предотвращение утечки через API

5. **Тегирование**
   - Тег: `confidentiality:medical`, `sensitivity:high`, `external:laboratory`
   - Применение: Специальные политики для внешних интеграций

## 7. Приоритеты внедрения защиты

### Фаза 1 (Критично - немедленно):
1. Шифрование медицинских карт (Rest + Transit)
2. Шифрование персональных данных (Rest + Transit)
3. Тегирование всех конфиденциальных данных

### Фаза 2 (Высокий приоритет - 1-2 месяца):
1. Обезличивание для аналитики
2. Маскирование в интерфейсах
3. DLP для внешних интеграций

### Фаза 3 (Средний приоритет - 3-6 месяцев):
1. Токенизация для некритичных систем
2. Расширенная обфускация в логах
3. Хеширование для поиска дубликатов
