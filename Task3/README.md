# Задание 3: Оценка Data Encryption at Rest and In Transit

## Описание

Это задание посвящено разработке стратегии защиты данных в системе «Медикаменте» с учётом особенностей шифрования данных в разных состояниях — при хранении (at rest) и во время передачи (in transit).

## Структура решения

### Документ

**Решение_Задание_3.md** - Полное решение задания, включающее:

1. **Сводная таблица защиты данных** - Реестр данных в формате задания: Данные | В чём необходимость защиты | Инструменты защиты

2. **Классификация данных и стратегия защиты** - Классификация данных по состоянию, чувствительности и профилю риска, реестр данных для защиты с инструментами

3. **Реестр программных и аппаратных средств защиты** - Полный реестр инструментов:
   - Инструменты шифрования at rest
   - Инструменты шифрования in transit
   - Инструменты контроля и мониторинга
   - Инструменты автоматизированного контроля

   - Бизнес-риски
   - Технические риски
   - Специфические риски медицинских данных
   - Количественная оценка рисков
   - Соответствие принципам Privacy by Design

## Ключевые результаты

### Классификация данных

Данные классифицированы по:
- **Состоянию**: at rest, in transit
- **Чувствительности**: Критическая, Высокая, Средняя, Низкая
- **Профилю риска**: Высокий, Средний, Низкий

### Инструменты защиты

**Data at Rest**:
- HashiCorp Vault (управление ключами)
- PostgreSQL TDE (шифрование БД)
- BitLocker/LUKS (полнодисковое шифрование)
- Veeam Backup Encryption (бэкапы)

**Data in Transit**:
- Kong API Gateway (mTLS, OAuth 2.0)
- TLS 1.3 для всех соединений
- HashiCorp Vault PKI (внутренние сертификаты)

**Контроль и мониторинг**:
- ELK Stack (логирование и аудит)
- Azure AD (IAM, RBAC, MFA)
- Apache Atlas (тегирование данных)
- Microsoft Purview DLP (предотвращение утечек)

### План внедрения

- **Фаза 1 (0-3 месяца)**: Критичные данные
- **Фаза 2 (3-6 месяцев)**: Расширение защиты
- **Фаза 3 (6-12 месяцев)**: Полная защита
