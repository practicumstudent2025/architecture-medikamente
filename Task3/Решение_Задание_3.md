## Классификация данных

### По состоянию
- **Data at Rest**: PostgreSQL, ClickHouse, Elasticsearch, Object Storage S3, бэкапы
- **Data in Transit**: API-вызовы, интеграции, внутренние коммуникации, синхронизация

### По чувствительности
- **Критическая**: Медицинские карты, результаты анализов, платежная информация
- **Высокая**: Персональные данные, договоры, финансовые документы
- **Средняя**: Контактные данные, логи, метаданные
- **Низкая**: Обезличенные данные, операционная статистика

### По профилю риска
- **Высокий** (🔴 Критично): Медицинские карты, результаты анализов, платежная информация
- **Средний** (🟠 Высокий - 🟡 Средний): Персональные данные, договоры, логи
- **Низкий** (🟢 Низкий): Обезличенные данные, операционная статистика

## Автоматизированный контроль

**Инструменты**: HashiCorp Vault Agent (ротация ключей), Apache Atlas (тегирование), Open Policy Agent (ABAC), ELK Stack + Prometheus (мониторинг), Microsoft Purview DLP (предотвращение утечек), Terraform + Ansible (автоматизация)

**Политики**: Автоматическое шифрование, тегирование, контроль доступа, аудит, обнаружение аномалий

# Обоснование необходимости защиты

## Правовые требования

### 152-ФЗ "О персональных данных"
- Обязательное шифрование персональных данных при передаче
- Контроль доступа на основе ролей
- Аудит всех операций
- **Штрафы**: до 18 млн руб. для юридических лиц, до 200 тыс. руб. для должностных лиц

### 323-ФЗ "Об основах охраны здоровья граждан"
- Врачебная тайна (ст. 13)
- Запрет разглашения сведений о факте обращения
- **Последствия**: Уголовная ответственность (ст. 137 УК РФ), репутационные риски

### PCI DSS (для платежных данных)
- Шифрование данных карт при хранении и передаче
- **Последствия**: Штрафы от платёжных систем, запрет на приём платежей

## Бизнес-риски

### Репутационные риски
- Утечка медицинских данных → публикация в СМИ → потеря доверия клиентов
- **Влияние**: Снижение выручки на 20-40%, долгосрочное восстановление репутации (1-3 года)

### Финансовые риски
- **Прямые потери**: Штрафы (до 18 млн руб.), компенсации (2-5 млн руб.), судебные издержки
- **Косвенные потери**: Снижение выручки (10-30 млн руб.), потеря партнёров
- **Оценка**: Средний инцидент утечки данных может стоить 5-15 млн рублей

### Операционные риски
- Взлом системы (ransomware), нарушение работы, потеря данных
- **Влияние**: Остановка работы клиники, невозможность обслуживать пациентов

## Технические риски

### Data at Rest
- **Угрозы**: Физический доступ к серверам, кража носителей, несанкционированный доступ к БД, инсайдерские угрозы
- **Решение**: Шифрование всех данных (AES-256), контроль доступа, аудит

### Data in Transit
- **Угрозы**: Перехват трафика (Man-in-the-Middle), подмена данных, анализ трафика, утечка через незащищённые API
- **Решение**: TLS 1.3 для всех соединений, mTLS для критичных интеграций, DLP

### Отсутствие контроля
- **Угрозы**: Невозможность отследить доступ, отсутствие обнаружения аномалий, невозможность расследования
- **Решение**: Полный аудит, SIEM для обнаружения аномалий, DLP

## Специфические риски медицинских данных

- **Высокая ценность**: Невозможно изменить, высокая чувствительность, долгосрочное хранение (10+ лет)
- **Реидентификация**: Обезличенные данные могут быть реидентифицированы
- **Интеграции**: Утечка через API лаборатории, недостаточный контроль у партнёров

## Количественная оценка рисков

| Категория данных | Вероятность | Влияние | Общий риск | Приоритет |
|------------------|-------------|---------|------------|-----------|
| Медицинские карты | Средняя (0.3) | Критическое (1.0) | Высокий (0.3) | 🔴 Критично |
| Результаты анализов | Средняя (0.3) | Критическое (1.0) | Высокий (0.3) | 🔴 Критично |
| Платежная информация | Низкая (0.2) | Критическое (1.0) | Высокий (0.2) | 🔴 Критично |
| Персональные данные | Средняя (0.3) | Высокое (0.8) | Высокий (0.24) | 🟠 Высокий |

### ROI защиты данных

**Инвестиции** (год 1): ~5.5-8.5 млн руб. (инструменты, внедрение, обучение)

**Потенциальные потери без защиты**: 12-53 млн руб. (штрафы, компенсации, потеря репутации)

**Вывод**: Инвестиции в защиту окупаются уже при предотвращении одного инцидента.

## Соответствие принципам Privacy by Design

- **Proactive not Reactive**: Защита заложена в архитектуру с самого начала
- **Privacy as the Default**: Минимальные права доступа, шифрование по умолчанию
- **Full Functionality**: Защита не мешает функциональности
- **End-to-End Security**: Защита на всех этапах жизненного цикла данных
- **Visibility and Transparency**: Полный аудит, прозрачность для пользователей
- **Respect for User Privacy**: Право на удаление и доступ к данным

## Заключение

Защита данных в медицинской системе «Медикаменте» является **критически необходимой** по причинам:
1. Правовые требования (152-ФЗ, 323-ФЗ, PCI DSS)
2. Бизнес-риски (репутационные и финансовые потери)
3. Технические риски (утечки, взломы, инсайдерские угрозы)
4. Специфика медицинских данных (высокая ценность, долгосрочное хранение)
5. Принципы Privacy by Design

**Рекомендация**: Внедрение защиты данных должно быть приоритетом №1 при разработке системы.
